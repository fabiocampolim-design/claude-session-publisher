# Contributing to claude-session-publisher

Thank you for considering a contribution. This file says how to report a
problem, how to propose a change, and the rules a change has to meet to be
merged. The machine-oriented description of the repository is `AGENTS.md`;
the human manual is `docs/USER_MANUAL.md`; the design decisions and their
trade-offs are in `docs/DESIGN.md`.

## Reporting

Open an issue in this repository. The reports that help most are the ones
the README asks for: a session that renders oddly, a fidelity report whose
numbers do not reconcile, a record type the page lists as unhandled, a
format that loses something the HTML still has, and anything from Linux or
macOS, where fewer real sessions have been run. Say which `--format`,
`--tool-output` and `--lang` you used and paste the fidelity block from the
page. A trimmed excerpt of the source `.jsonl` (the offending records plus a
few around them) makes a bug reproducible; the file holds your whole
conversation, so trim before pasting and never attach it whole.

## Proposing a change

1. Open an issue first for anything larger than a typo, so the scope is
   agreed before the work is done.
2. Fork, branch, and keep the change to one topic.
3. **Failing-first test.** Every bug fix starts with a check that fails on
   the current code and passes on the fix; every feature comes with its
   checks. `pyflakes` must be clean over the whole tree.
4. Run the suite locally before opening the pull request, once with a TeX
   installation on `PATH` and once without (the LaTeX and PDF checks skip
   themselves, everything else must still pass):

   ```
   python -m pyflakes transcript_archiver.py tests docs examples
   python tests/test_archiver.py
   python tests/test_githubify_conformance.py   # the vendored publishing checker's wiring test
   ```

   (`python -m unittest discover -s tests` would import `test_archiver.py`
   and run the whole suite a second time as a side effect; run the two
   files directly.)

5. Keep the documentation in step: `README.md`, `AGENTS.md`,
   `docs/USER_MANUAL.md` and `CHANGELOG.md` describe the same program, and
   the suite fails when a CLI flag, a metadata key or the check count named
   in prose drifts from the code. Rebuild the manual with
   `python docs/build_manual.py` after editing it.
6. **Nothing is dropped silently.** Every source record is rendered, folded
   into an earlier turn, or counted, and the three are reconciled against the
   source on the page. A new record type is counted and reported until it is
   understood; a change that skips records "because they are noise" will not
   be merged.
7. **Human turns are verbatim** in every format. No markdown rendering, no
   trimming, no reflow of what the user typed or pasted.
8. **The archiver's own words are translatable; the conversation never is.**
   A new heading, label or note is a literal inside `_()` with all four
   translations (pt-BR, es, de, fr) in the same commit; the suite scans for
   strays. Logs, console output and `--help` stay English.
9. **Standard library only, one file.** No runtime dependency; `xelatex` and
   `pandoc` are optional external programs the code detects and degrades
   without.
10. **Check the artefact, not the exit code.** A change to the LaTeX or PDF
    path comes with a check that reads the produced file back (page count,
    extracted text) and, before a release, a run over a few real sessions of
    the maintainer's own archive in every format.
11. Every new source file carries the SPDX header
    (`# SPDX-License-Identifier: Apache-2.0`).
12. Do not bump `VERSION`, `CITATION.cff` or tag a release in a pull request;
    the maintainer does that on merge.

## Contributions made with AI assistance

Welcome, on two conditions: say so in the pull request (which tool, what it
did), and state what *you* verified: the check you ran, the page you read,
the PDF you opened. This repository was itself built with an AI assistant
under a check-everything contract (see "How it was built" in `README.md`);
the same standard applies to contributions.

## Licensing

By submitting a contribution you agree that it is licensed under the
repository's licence (Apache License 2.0), as section 5 of that licence
provides for intentional submissions. Do not contribute code or text you do
not have the right to license that way, and never add a real transcript,
yours or anyone else's, to the tracked tree: the examples are synthetic and
generated by `examples/make_sample.py`.

## Conduct

Everyone interacting in this repository is expected to follow
`CODE_OF_CONDUCT.md`.
